- [event 2026-10-16] Run started, Create mode, coaching path.
- [decision 2026-10-16] Stakes: consumer — intended as a real, shipped app, not just a learning demo.
- [decision 2026-10-16] Core problem: sellers run auctions in Facebook comments; at high comment volume, tracking bids becomes unmanageable.
- [decision 2026-10-16] Categories: mixed (clothes, watches, collectibles, etc.) — UI must be category-agnostic.
- [decision 2026-10-16] Listing pricing fields today: base price, bid increment, steal price, buyout price (+ others). Exact semantics of steal vs buyout pending.
- [decision 2026-10-16] Buyers currently bid by typing amounts in comments.
- [decision 2026-10-16] Form factor: any device that can open Facebook — multi-surface (phone + desktop browser).
- [decision 2026-10-16] Post-win: seller messages the winner directly; no in-app payment.
- [decision 2026-10-16] Pricing: base price, bid increment, buyout price. "Steal" dropped.
- [decision 2026-10-16] Surfaces: buyers bid in the browser from a shared link, no install required; native app optional (Flutter mobile + Flutter web, one codebase).
- [decision 2026-10-16] Facebook remains the shop window (link posted in groups); all bidding happens on BidBoard.
- [decision 2026-10-16] Scope: support multi-item, open-ended bidding (semantics pending).
- [decision 2026-10-16] Auction modes: seller chooses timed OR open-ended (manual close), for a single item OR a multi-item batch.
- [decision 2026-10-16] Buyer identity: Sign in with Facebook and Sign in with Google. No anonymous bidding.
